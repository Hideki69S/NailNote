## デザイン方針

コンセプトは「Premium Soft Glass」。可愛らしい色と丸みを生かし、薄い光の縁、柔らかい奥行き、控えめな艶で上品さを加える。

- 背景9種類、デザインカード9種類、レインボーの行ごとの色変化、既存の設定キーと初期値を維持する。
- ローズ・ゴールドなど特定の色を質感の前提にしない。色は既存パレット、光と影は色相に依存しない共通の規則で扱う。
- 写真と文字を装飾より優先し、写真の上へ反射・ぼかし・色フィルタを重ねない。
- 濃色／淡色のカードテーマと、端末のライト／ダーク表示を別々の条件として評価する。
- 第1候補はEntryListView.swift内の描画調整。共有部品の既定値を一括変更しない。
- AIは引き続きクローズ。3タブ、バッジ・メニューの非表示、評価・通信の遮断を維持する。
- 機能、情報の意味、CoreData、写真読込・保存、ソート・検索、編集遷移、削除、自己評価の値は変更しない。

## 2. 背景・枠線・影・角丸の現状

### 描画の積み重なり

```text
GlassBackgroundView：ページ背景グラデーション＋ぼかした光
  List：行背景は透明、区切り線なし
    GlassCard：外側のテーマ色背景・枠線・影
      ZStack
        EntryCardGlowLayer：内側の色面・2本の枠線・影
        HStack：写真＋テキストとタグ
```

| 部位 | 現在の実装 |
|---|---|
| 外側背景 | EntryRowViewがouterFillTop／outerFillBottomの左上→右下グラデーションをGlassCardへ渡す。GlassCardのカスタム背景経路はそのグラデーションで塗り、同じものをopacity 0.22でも重ねる |
| 実際の透過 | デザインカードのカスタム背景と内側glowFillは不透明の色であるため、現在の主要面からページ背景は実質的に透けない。透明なList背景とカードの透明度は別のもの |
| Material | GlassCardはカスタム背景がない場合だけregularMaterialを使用。デザインカードはカスタム背景経路のため、同じMaterial処理は通らない |
| 外枠 | outerStrokeStart／outerStrokeEndのグラデーション、線幅1.25pt。既存パレットの線色には0.90〜0.96程度の不透明度が設定されている |
| 外形 | 共通cardCornerRadiusは15pt、continuous。GlassCardが枠と内容を同じ外形でクリップした後、外側へ影を付ける |
| 外側の影 | 共通cardShadowColor＝黒0.15、radius 12、x 0、y 8 |
| 内側面 | EntryCardGlowLayerは角丸11pt（15−4）、glowFillTop／Mid／Bottomのグラデーション。横−2pt・縦−4ptのpaddingで内容領域より広げる |
| 内側の線 | テーマ色の線幅1.0ptと、角丸9pt（15−6）・白0.22・線幅0.7pt・padding 1の線を重ねる |
| 内側の影 | 黒0.08、radius 10、y 6。外側の影と重なる。光レイヤーはallowsHitTesting(false) |
| 写真 | 88×88pt、scaledToFill、角丸20pt。テーマ色の枠1.6pt。枠に黒0.10・radius 4・y 2の影、写真全体に黒0.08・radius 10・y 6の影 |
| 日付・自己評価の見出し | EntryInfoTag。白0.74のカプセル、テーマのtagTextとtagStroke、枠0.7pt |

現状は装飾レイヤーを複数持つ。追加の影・白い面をそのまま増やすと、輪郭の硬さ、白浮き、影の濁りが増える懸念がある。これはコードから考えられる改善余地で、実画面での見え方を断定したものではない。

## 3. 写真・文字・タグのレイアウト

| 項目 | 現在の構造と制約 |

| 一覧の行 | sortedEntriesを列挙しcardIndexを渡す。中央寄せのHStack内にEntryRowViewを置く。Listの行余白は上下6pt、左右0。透明なNavigationLinkを重ね、カードタップでEditEntryViewへ遷移 |

| 写真と文章 | HStackの間隔18pt。写真は右へ5ptオフセット。右側はleadingのVStack、間隔10pt |
| タイトル | sparklesアイコン＋タイトル＋Spacer。headline／semibold、1行、minimumScaleFactor 0.6、allowsTightening。空タイトルは「（タイトルなし）」 |

## 4. 設定テーマとの連携

```text
SettingsViewのPicker
  → BindingからAppStorageへrawValueを書込
    → ThemeBackgroundPreset → GlassBackgroundView
    → ThemeDesignCardPreset → EntryRowView等 → DesignCardPalette
    → ThemeItemCardPreset → 用品画面
```

背景とカードは別々に選択できる。ノワール背景で淡色カード、その逆の組み合わせも想定する必要がある。設定キー、列挙型のrawValue、既定値は変更しない。

| 種類 | 維持するバリエーション |
|---|---|
| ページ背景（9種類） | スモーキーセージ、ストーンローズ、ミストブルー、グラファイトミント、アイボリーコーラル、ノワールシルバー、ノワールゴールド、アイボリーゴールド、レインボー |
| デザインカード（9種類） | ローズシャンパン、モーブブロンズ、セージゴールド、スレートブルー、テラコッタクリーム、ノワールシルバー、ノワールゴールド、アイボリーゴールド、レインボー |

レインボーのカード本体はvariantIndex＝cardIndexを使い、赤・橙・黄・緑・シアン・青・紫の7色を循環する。一方、EntryThumbnailViewとEntryInfoTagは現在variantIndexを渡さず、既定の0番を参照する。カード本体と装飾で色が揃わない原因になり得る。検索・並べ替え後に行番号によって色が変わる現仕様自体は維持し、記録IDによる色固定へは変更しない。

### 明暗テーマと視認性の懸念

- ノワール系のtitleText／tagTextは明るく、glowFillは濃い。白0.74の情報タグ背景は、その明るいtagTextと組み合わせるとコントラストが低くなる可能性が高い。
- 例として、noirSilver／noirGoldのglowFillMidに白0.74を重ね、tagTextと比較する単純なsRGB合成計算では、どちらも概算約1.24:1となる。これは実機画像の測定ではなく、枠・グラデーション位置・OSの描画差を除いた懸念の確認用の値。
- 日付のsecondaryやカラー名のprimaryは端末の表示モードに追随する一方、カスタムRGBのカード面は同じ明暗のまま。端末ライト＋濃色カード、端末ダーク＋淡色カードを個別に確認する必要がある。
- 既存の描画には、カード面の明暗による文字色の統一や、Reduce Transparency／Increase Contrastを明示的に受ける分岐は見当たらない。標準Materialやシステム色の内部挙動まで無効と判断したものではない。

## 6. 最小変更の具体案

### 第1候補A：EntryListView.swiftだけで改善する

| 変更箇所 | 具体案・試作の初期値 | 目的と影響制御 |
|---|---|---|
| EntryCardGlowLayer | 既存のglowFillと外側のテーマ色を保持。内側の影を外し、外側の共通影を主な浮き影として使う。テーマ色の内枠は1.0→0.5〜0.75ptを比較 | 影と輪郭の重複を整理し、厚ぼったさを抑える。GlassCardの既定値や用品には触れない |
| 内側ハイライト | 全周が一様な白0.22の線を、左上が明るく右下へ弱まる0.5〜0.75ptの線へ置換。白の最大不透明度0.10〜0.18を試す。写真・文字より背面の内側面に限定 | 色相を加えず、薄いガラスの縁と方向性のある艶を表現。白い面で濃色テーマ全体を明るくしない |
| EntryInfoTag | 白0.74の塗りを、既存glowFillの明暗に沿う面へ変更。文字は同じパレットのtagTextを維持し、細いテーマ枠で分離。濃色面へ白を足すなら0.04〜0.08程度から確認 | 明るい文字と白いタグの衝突を避ける。見出し文言・情報量・操作は維持 |
| 日付・カラータグの文字 | 日付はパレット由来の明暗対応色（tagText等）へ揃える。カラータグは淡い色面を残し、文字をtitleText等へ揃える案を比較 | 端末モードだけで文字色が変わる組み合わせを減らす。カラー分類そのものの色は維持 |
| 写真枠・影 | 写真サイズ・読込・トリミングは維持。装飾枠を1.6→0.75〜1.0ptへ抑え、枠側の小影を外して全体の影1つへ整理する案を比較 | 写真を主役にする。写真へ艶のオーバーレイを重ねない |
| パレットの受渡し | Rowで解決したパレットをEntryInfoTagとEntryThumbnailViewに任意引数で渡し、レインボーの色番号を揃える。既定のパレット解決を残して他の呼び出しへ配慮 | 同じ設定値を使いながら、行内の色の整合性を上げる。AppStorageの保存値は変更しない |
| 装飾の操作性 | 追加・置換する光のレイヤーにはallowsHitTesting(false)。装飾だけの要素はアクセシビリティで読み上げない | 既存NavigationLinkとスワイプ削除の操作を妨げない |

第1候補Aは不透明な色面を基本としており、透明感は縁の光・艶・影の整理で表現する。**ページ背景の実透過を追加したものとは呼ばない。** まず読みやすさとテーマ維持を確認し、実透過が必要かを判断する。

カード・写真の外形、写真88pt、最大幅360pt、行間、情報順序は初回では維持する。タイトルの0.6縮小を強める方法で収めない。長文・Dynamic Typeで問題が再現した場合は、別の小さな変更としてタイトル最大2行／日付と評価の縦積みを検討する。文字サイズや横幅の変更は、装飾だけの変更と混ぜて判断しない。

### 必要時の第2候補B：実透過と外枠の調整を選択適用

第1候補Aの比較後、実際の背景透過や外枠・外影の調整が必要な場合に限り、EntryListView.swiftとGlassCard.swiftの2ファイルを対象にする。

- GlassCardへ任意の外観指定を追加し、既定の描画・影は現状のままにする。Premium Soft Glassを選ぶのはEntryRowViewだけとする。
- 外枠は0.75〜1.0pt、外影は黒0.10〜0.14・radius 10〜14・y 4〜6を試作初期値とし、別の影を追加して強めない。濃色背景では影の濃さより光の縁で分離する。
- 実透過を試す場合は、二重の不透明背景と内側の不透明面を積んだままopacityを付けない。色面を整理し、文字の背面にある主面の合成後の不透明度がおおむね0.90〜0.96になる範囲から試す。既存パレットの色相と明暗を保持する。
- 不透明な面にMaterialを重ねるだけでは背景は透けない。透過させる経路を1つに絞り、Materialの採用自体も比較対象とする。カード全体へopacityを指定して文字と写真まで薄くしない。
- Reduce Transparencyでは実透過をやめて既存パレットの不透明面へ戻す。Increase Contrastでは面の不透明度・文字・境界を優先する。これらは候補Bを実装する場合の条件。
- グローバルなcardCornerRadius、cardShadowColor、cardFillGradientやパレットのRGBを置換しない。用品・広告・設定など、既定呼び出しの表示は変えない。

候補Bは初回から必須ではない。候補Aの実装前から共有コンポーネントを拡張することは推奨しない。

### 共通する質感の具体案

質感は3案共通の補助であり、主な変化は上記の写真サイズ・情報配置・余白によって作る。

- 情報面はglowFillTop／Mid／Bottom、外周はouterFillTop／Bottomを引き継ぐ。Cはヘッダー・中央・フッターの面を同系色の明度差でつなぎ、太い二重枠や別色のパネルを増やさない。
- 上左からの細いハイライトは第1弾の0.6pt・白0.16→0.06→0を初期値として維持し、カード面だけに置く。光を強くして変化量を稼がない。

- 日付・自己評価は大きなカプセルをやめ、小ラベル＋値の組にする。カテゴリだけを高さ28pt以上・左右10〜12pt・枠0.6〜0.8ptの柔らかいカプセルに統一する。背景は行の色面、文字は行のtitleText／tagText、カラーの色丸は維持する。
- 星の既存グラデーションは共有部品側で変更しない。隣にテーマ対応色の数値を置いて、星だけのコントラストに依存させない。数値を付けても星の視認性問題が完全に解決するとは扱わず、実際の色を検証する。
- タップ対象はカード全体のまま。カプセルをボタンに見せる強い影や押下表現は加えない。装飾はヒットテストと読み上げを妨げない。

### 3案の比較と推奨

| 比較軸 | A：現行強化 | B：写真主役 | C：プレミアム |
|---|---|---|---|
| 写真の基準領域 | 112×112 | 336×196（全体表示優先） | 144×144 |
| タイトルの基準幅 | 200 | 328 | 328 |
| 高さ目安・2行タイトル | 約212 | 約374 | 約295 |

| 実装難易度 | 低〜中 | 中、画像品質・負荷の確認が多い | 中、可変レイアウトの確認が必要 |

**推奨はC。** 写真とタイトルの双方を大きくし、日付・自己評価・カテゴリの役割を分けるため、装飾を派手にせずに現行との差を出しやすい。写真鑑賞を最優先するならB、一覧の密度と小さな変更範囲を最優先するならAが適する。Cの採用は決定しておらず、ユーザーが選択するまで実装しない。

### SwiftUIでの具体的な実装計画

#### P0：同条件の比較を準備する

- 使用した背景・カードのrawValue、端末OS、表示モード、文字サイズ、アクセシビリティ設定を確認する。現状の青系を特定のプリセット名と推測して保存しない。

- 可能なら元解像度の実機画像を使う。今回の添付だけで正確なpt値や微細な光の強度を測定したとは扱わない。

#### P1：金属リムを「線」から「面」へ変える

- 対象：EntryCardGlowLayer。ファイル内privateの表示部品に、例としてHybridMetalRim／HybridPearlFaceを分ける。新規ファイル・ターゲット登録は不要。

- リムの周方向にはAngularGradientまたはマスクしたLinearGradientの組を使い、上左の明るい反射・右側の中間色・下右の暗い返りを作る。色は既存outerStrokeStart／End、glowStroke、白・黒の低不透明度を役割ごとに合成し、固定の金色にしない。
- 幅方向は、外側の細い明部と内側の短い暗部を別マスクに分ける。現在の線の本数を増やす方式にはしない。既存の1pt／0.65pt線は新しい面・境界の役割へ置き換える。
- 初期比較値：帯幅2.5／3／3.5pt。写真・文字の配置とカード高さは変えず、各値を実機の通常倍率で比較する。これらは提案値であり未実装。

#### P2：パール面・反射・内周の陰影を独立させる

- 対象：EntryCardGlowLayerとEntryRowViewのbackground。既存の外影（接地：黒0.06・radius 2・y 1、浮き：黒0.13・radius 12・y 7）は初回では増やさない。

- 反射の帯が必要なら、正規化した座標のShapeとPathの曲線で静的なマスクを作り、そこへグラデーションを流す。帯はカードの一部分に留め、写真や文字の上を白く横切らせない。常時アニメーションや大きなガウスぼかしは追加しない。
- 内周の陰影は、内側のRoundedRectangleをoffsetしたマスク等で切り出す。初期幅0.5〜1.5pt、下右の暗さ0.08〜0.14程度、上左の局所光0.12〜0.24程度を比較する。淡色・濃色で同じ不透明度を固定しない。

- 対象：EntryThumbnailViewのframePadding > 0の装飾経路だけ。既定framePadding 0の呼び出し、size、loadThumbnail、scaledToFill、写真自体のクリップを維持する。
- 現在のフレーム用3色面を、外縁・傾斜面・写真との接合部へ分離する。カードの光源と同じ上左を明るく、下右を暗くする。
- 接合部の陰影はフレーム内にmaskし、写真の上へ影の面を被せない。フレームだけの接地感を先に作り、写真全体のradius 8の影を濃くすることを最初の対策にしない。
- 写真の彩度・露出・シャープネスや保存画像を加工しない。参考の写真と同じ印象を、画像フィルタで作る計画ではない。

### 曲面の描画仕様

各折り目の中心を`base + slope × u + bend × u²`とする放物線で定義し、その周囲にガウス型の高さ断面を置いた。高さ場の微分から法線を算出して、左上方向の拡散反射・弱い鏡面反射・稜線の反射・谷の遮蔽を合成する簡易モデル。物理的に厳密な布のBRDFや光線追跡ではない。

- 背景fabricは7本の広さ・高さが異なる曲面。中心線パラメータ`(base, slope, bend)`は`(-0.03, 0.36, -0.34)`、`(0.11, 0.45, -0.38)`、`(0.49, -0.52, 0.24)`、`(0.40, -0.52, 0.24)`、`(0.70, 0.42, -0.36)`、`(1.12, -0.58, 0.12)`、`(0.93, -0.20, -0.32)`。幅は正規化座標0.025〜0.075、高さ0.014〜0.065。上端・操作部品の余白・下端にも曲線が読める配置とした。
- glassは2本の緩やかな斜め曲面、tabは2本の広い曲面を使用。背景と同じ布の起伏をカードへそのまま縮小する構成にはしていない。glass／tabの右側中央は、読み取り領域の指数関数マスクで反射を最大75％弱める。これは文字の実際の領域を検出する処理ではなく、表示用の固定した減衰領域。
- 背景の連続した繊維反射は振幅0.004の正弦成分で、ごく弱い表面変化だけを作る。乱数粒・発光・アニメーションはない。拡大時の織り目を再現したものではない。
- 最初の描画比較では陰が黒すぎたため、最終版では背景の黒合成を淡色最大0.16／濃色0.22に制限。白合成は最大0.46／濃色0.24。カードglassは淡色で白最大0.30・黒最大0.09とし、反射を抑制する。濃色は同じ色へ変換せず、元のパレットに低い白反射を合成する。
- RGBAの静止面は表示幅を元に64〜384px、縦横比に合わせて高さ32〜1024pxで生成。縦横比ごとに計算するため、固定の縦長素材を画面へ引き伸ばす方式ではない。滑らかな曲面の補間を前提とし、画面の全解像度で細かな布を描いたものではない。
- NSCacheの目安上限は24MiB。キーは素材種別・計算寸法・淡色／濃色。テーマの元色は既存背景・カード面で維持し、生成面は光と影のみ。キャッシュが追い出された場合は再計算する。初回生成はCPU計算であり、実機の初期表示停止時間は未測定。
- タブバーの画像は公開UITabBarAppearanceの背景として渡し、OSの背景マスク・選択カプセルを維持。ベベルは背景画像内の装飾であり、別の外形やタップ領域ではない。OSでのクリップや色の反映は異なる可能性がある。
