# AI評価機能の一時クローズ：調査結果と変更計画

作成日：2026-10-26

## 状態と目的

本書は調査結果と変更計画を保存したものであり、実装は未着手・承認待ち。
今回許可された作業は本書の新規保存のみ。Swiftコード、CoreDataモデル、Xcode設定、その他の既存ファイルは変更しない。

開発方針は、AI評価を当面クローズし、ネイル記録・用品管理など基本機能の完成を優先する。AI関連コードと保存済みデータは保持し、将来の再開に備える。

調査はリポジトリの静的確認による。AGENTS.md、ルートおよびアプリ配下のPROJECT_STATUS.md、nailnote-devスキル、Swiftコード、CoreDataモデル、Xcodeプロジェクトの参照情報を確認した。ビルド・実機検証・API実行は未実施。
以下のファイルパスはリポジトリルートからの相対パス。行番号ではなく型・処理名を変更箇所の目印とする。

## 推奨方針

- 共通の固定フラグ（案：`NailNoteFeatureFlags.aiEvaluationEnabled = false`）でAIの表示と実行を制御する。
- AIタブを構築せず、通常表示を「デザイン／アイテム／設定」の3タブにする。
- AI画面以外のバッジ、並べ替え項目、設定、説明文も非表示または基本機能用の文言へ切り替える。
- 評価サービスの入口と実通信関数の入口で、同じフラグによる実行遮断を行う。
- フラグはユーザー設定にせず、Debug／Release共通で無効とする。
- コード・型・CoreDataモデルは残し、ターゲット除外やデータ移行を行わない。

新規Swiftファイルのターゲット登録を避けるため、フラグの定義は既存のRootView.swift内に置く最小変更案とする。フラグを戻すだけで公開可能と判断せず、再開時にはAPI実装と動作を改めて検証する。

- 実行確認ダイアログの「AI評価を実行」「キャンセル」と写真送信の説明。

- 総合・5項目評価、コメント、レーダーチャート、同カテゴリの前回比較、直近6件の推移グラフ。

## API通信の呼び出し元と実行条件

確認できた通信経路は1系統。

```text
RootViewのAIタブ
  → SimHomeView内の評価生成／再評価ボタン
  → entryPendingConfirmationを設定
  → 確認ダイアログで「AI評価を実行」
  → TaskからSimHomeView.evaluate(entry:)を実行
  → AINailScoreService.shared.evaluate(...)
  → performRemoteEvaluation(...)
  → URLSession.data(for:)
```

通信・サービス処理はすべて`NailNote/Features/Sim/SimHomeView.swift`内にある。

| 段階 | 現在の実行条件・処理 |
|---|---|
| 評価ボタン表示 | 写真IDがあり、未評価の場合。評価済みの場合は写真ハッシュ確認完了後、写真が変わったと判定された場合 |
| 画面側の実行 | 確認ダイアログで許可。写真IDがあり、別の評価を実行中ではないことを確認 |
| サービス側の前処理 | フル画像またはサムネイルを読み込み、縮小・JPEG変換。現在の記録の保存済みハッシュと同一なら拒否 |
| 利用回数 | 月別UsageQuotaを取得または作成。Releaseは月3回未満。DEBUGでは上限判定を省略 |
| キー判定 | 環境変数の非空OPENAI_API_KEYを優先し、次にInfo.plistを確認 |
| キーあり | `https://api.openai.com/v1/responses`へPOST。モデル指定は`gpt-4o-mini` |
| キーなし | モック結果を生成。通信はしないが、結果保存と回数加算を行う |
| 成功後 | EntryAIScoreBridgeへ結果を書き込み、利用回数を加算し、CoreDataを保存 |

起動、記録保存、バックグラウンド処理、タイマー、ディープリンクからの自動評価経路は見当たらない。AIカードの`.task`は写真ハッシュ確認であり、API通信ではない。

### 通信停止方法

1. AIタブと画面内容を構築せず、ユーザー操作からの実行経路を閉じる。
2. `AINailScoreService.evaluate(...)`の最初で共通フラグを確認し、無効なら専用の無効化エラーを返す。写真読込、利用枠作成、キー判定、モック生成、結果保存より前に停止する。
3. `performRemoteEvaluation(...)`の入口でも同じフラグを確認し、リクエスト送信に到達させない。
4. Debug／Release、APIキーの有無にかかわらず停止する。

キーを外すだけではモック生成・保存が続くため採用しない。アプリ全体のネットワーク制限も行わず、用品URL、ShareLink、サポートリンクへの影響を避ける。

この計画は変更を組み込んだアプリでの停止を対象とする。すでに配布・起動済みの旧版を遠隔停止する機構ではない。

## 保持するコード・モデル・データ

| 対象 | 保持方法・理由 |
|---|---|
| SimHomeView内の画面、チャート、比較、サンプル、通信、モック | 型と処理をビルド対象に残し、入口を遮断。再開時に再利用する |
| EntryListView内のEntryAIScoreBridgeとNailEntry拡張 | そのまま保持。既存の読み書きと型依存を壊さない |
| `NailNote/Core/NailNote.xcdatamodeld` | EntryAIScore、UsageQuota、NailEntry.aiScoreを含む全モデルを変更しない。属性・関係・削除規則・Codegen設定を維持 |
| CoreData関連Swiftクラス | 削除・再生成・ターゲット登録変更を行わない |
| 保存済みAIスコア・利用回数 | クローズ適用時に一括削除・初期化しない。新規評価による更新は遮断 |
| `NailNote/Design/GlassTheme.swift` | AIチャート用の型・色定義・キーを保持 |
| AIテーマ・AIソートの保存値 | 保持。AIソートは停止中だけ実効値を日付にする |
| 写真ストア・用品管理・自己評価 | 停止対象にせず、既存実装を維持 |

クローズ自体では既存AIデータを消さない。ただし基本機能の整合性を維持するため、次の既存処理は継続する。

- 記録を削除した場合、その記録のAIスコアも削除する。
- 記録写真を変更・削除した場合、古い写真に対するAIスコアを削除する。
- 写真を変えない通常編集では、既存AIスコアを保持する。

したがって「保持」は全データの永久凍結を意味しない。写真が変わっても古い評価を残す仕様変更は本計画に含めない。

## 変更範囲と対象外

実装を承認された場合のSwift変更対象は、RootView.swift、SimHomeView.swift、EntryListView.swift、AddEntryView.swift、EditEntryView.swift、SettingsView.swiftの既存6ファイル。

CoreDataモデル、写真保存処理、用品管理処理、Xcode設定、旧構成は変更対象外。前回調査で見つかった関連データ削除・保存失敗時の整合性、AI画像送信・レスポンス解析の問題も、このクローズ作業では修正せず別タスクとする。

AGENTS.mdとnailnote-devスキルには「4タブ固定」の記述がある。今回の新方針を優先し、将来の実装承認後には「AIクローズ期間中は3タブ」の例外と再開時の扱いをドキュメントへ明記する計画とする。Swift変更後にはPROJECT_STATUS.mdへ停止範囲、保持対象、検証状況、次の作業を記録する。

今回のドキュメント保存では、これらの既存文書も変更しない。

## 承認後の検証・完了条件

- Debug／Releaseでビルドを確認する。
- AIタブ、スコアバッジ、AIソート、AIテーマ設定、AI案内文が表示されない。
- 写真変更・削除と記録削除の確認ダイアログにAI文言が残らない。
- 過去にAIスコア順を保存した状態でも、日付順で正常に表示できる。
- APIキーの有無にかかわらず、サービスが通信・モック生成・利用枠作成・回数更新より前に停止する。
- 通信スタブまたは通信計測で、評価サービス呼び出し時にリクエストが送られないことを検証する。実APIへの送信は停止確認に不要。
- クローズ適用と再起動だけでは、既存AIスコア・利用回数が変更されない。
- 記録・用品の追加、編集、検索、並べ替え、写真操作、自己評価、お気に入り、URL共有、通常テーマ設定が従来どおり動作する。
- 記録削除と写真変更時の既存AIデータ整理処理が維持されていることを確認する。既知の削除不具合とクローズによる回帰を区別する。

## 再開条件

AI再公開には別途承認が必要。フラグを有効にする前に、画像入力とレスポンス解析、モックの識別、数値検証、保存・利用回数管理、配布時のキー管理を再確認する。AI実行の確認ダイアログとEntryAIScoreBridge経由の保存方針は保持する。
